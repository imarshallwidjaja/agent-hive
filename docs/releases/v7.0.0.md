# Agent Hive v7.0.0

Released: 2026-11-27

Agent Hive v7.0.0 moves the OpenCode v2 entry to OpenCode 2.4.2 and reduces what Hive puts into an agent's context. Tool results are compact JSON, `hive_status` and plan outlines return less by default, Worklog reads return each briefing once, exploration updates return a short receipt, and v2 requests leave out the tools Hive always refuses. On v2, the selected route and standing constraints move into a session instruction entry that survives native compaction. The release is a major version because the results of nine tools change shape, every JSON result loses its indentation, unused `hive-core` APIs are removed, and the v2 entry is qualified on 2.4.2 only.

Both host entries remain in the one `oc-arkive` package. OpenCode v1 keeps its floor of 1.18.30. OpenCode v2 is qualified on 2.4.2 only. Each host registers 50 Hive tools and 18 commands, compared with 50 and 17 in v6.0.0. The VS Code companion still requires VS Code 1.67.0 or later.

## Install and upgrade

These steps upgrade from v6.0.0. From v5.2.0 or v5.3.0, also apply the v6.0.0 changes in its [changelog entry](https://github.com/imarshallwidjaja/agent-hive/blob/v7.0.0/CHANGELOG.md#600---2026-11-22). From a release before v5.2.0, install v7.0.0 directly and also follow the lock and recovery procedure in the [Operator Guide](https://github.com/imarshallwidjaja/agent-hive/blob/v7.0.0/docs/OPERATOR-GUIDE.md#upgrade).

1. Finish or abandon live workers on the hosts you are upgrading.
2. On OpenCode v1, set the plugin entry to `oc-arkive@7.0.0`, or refresh the cached `@latest` package.
3. On OpenCode v2, plan the host upgrade first. OpenCode 2.4.2 adds a `machine` table to the native database on its first start, and starting 2.3.2 on a home that 2.4.2 has opened has not been tested. Quiesce and stop the 2.3.2 host and keep a copy of its native home, or give the 2.4.2 host a new home, as described in [Switching OpenCode hosts and rollback](https://github.com/imarshallwidjaja/agent-hive/blob/v7.0.0/docs/OPERATOR-GUIDE.md#switching-opencode-hosts-and-rollback). A home that 2.4.1 has already opened runs no new migration. Then upgrade the host to 2.4.2 and install this version in the npm install root, for example `/absolute/install`. The `plugins` entry keeps naming the installed `dist` directory, `/absolute/install/node_modules/oc-arkive/dist`.

   ```bash
   cd /absolute/install
   npm install oc-arkive@7.0.0
   ```

   A v2 host that stays on 2.3.2 keeps `oc-arkive@6.0.0`. The [plugin README](https://github.com/imarshallwidjaja/agent-hive/blob/v7.0.0/packages/opencode-hive/README.md#opencode-v2) covers v2 options, the session reader and host setup.
4. Install `vscode-arkive.vsix` from this GitHub Release with `code --install-extension ./vscode-arkive.vsix`.
5. Update custom instructions, commands and scripts that read the tool results listed under [Breaking changes](#breaking-changes). Parse JSON results instead of matching their indentation.
6. Restart the long-lived host process that loads the plugin, such as the `opencode` TUI, `opencode serve`, or its service. Restarting an attached client does not reload the server's plugin.
7. After the restart, send a new message in each session before using Hive tools, and launch fresh child sessions.

Existing plans, tasks, context, Worklogs, explorations and worker state are read as before, and no migration flag is required. A session record that holds only the flattened `standingConstraints` string from an earlier version is read as one `legacy` entry, and the next constraint write stores entries only. Task records that still hold `subtasks` or `aggregateBranchDiff` stay readable. Hive no longer writes or reads feature-local `sessions.json` projections, and it does not delete them.

### Rolling back to v6.0.0

Rolling back from v7.0.0 to v6.0.0 has not been exercised end to end, for a v1 plugin downgrade or for a v2 host. v6.0.0 cannot read a session or feature constraint register whose entries, joined by blank lines, exceed 8,000 UTF-16 code units, so under v6.0.0 such a register also cannot be edited or cleared. v7.0.0 accepts up to 16,000. The registers live in the project's `.hive/` directory, which stays in place through a rollback.

Before you stop v7.0.0, follow [Rolling back to 6.0.0](https://github.com/imarshallwidjaja/agent-hive/blob/v7.0.0/docs/OPERATOR-GUIDE.md#rolling-back-to-600) in the Operator Guide. Settle live writers, save the exact text of every directive, and check every session and feature register, including the registers that child sessions captured at dispatch. With the operator's approval, remove only directives that no longer apply, through guarded constraint edits. Under v6.0.0, start fresh children instead of continuing one whose captured register is over the limit. A saved copy does not keep a directive active. If the directives that must stay in force do not fit in 8,000 code units, postpone the rollback.

Then roll the host back, stopping it before you change anything. On OpenCode v1, set the plugin entry to `oc-arkive@6.0.0` and restart the long-lived process that loads the plugin. On OpenCode v2, quiesce and stop the 2.4.2 host, restore the copy of the 2.3.2 home or switch back to it, and run this in the npm install root; the `plugins` entry keeps naming `/absolute/install/node_modules/oc-arkive/dist`:

```bash
cd /absolute/install
npm install oc-arkive@6.0.0
```

Then start 2.3.2. Native conversations and jobs that started under 2.4.2 stay in the 2.4.2 home.

## Breaking changes

### OpenCode v2 2.4.2

The v2 entry builds against `@opencode/plugin`, `@opencode/client` and `@opencode/schema` 2.4.2. When a child stops, 2.4.2 posts a `<background-result kind="subagent">` message, and agent guidance waits for that message. v7.0.0 is not qualified on 2.3.2.

### Tool results

| Tool | v6.0.0 result | v7.0.0 result |
| --- | --- | --- |
| `hive_status` | Every task row carries every field | `done` and `cancelled` rows carry only `folder`, `status`, `hasHandoff`, `specStale` and `specStaleReason`; pass `detail: 'full'` for every field. The feature summary adds `hasExecutionDecisions`. |
| `hive_plan_read({ mode: 'outline' })` | Each `headings` entry is `{ level, title, path }`; the result also has `taskList` | Each `headings` entry is `{ level, title, line }`, and level-4 and deeper headings inside `## Tasks` are left out. `taskList` is removed. `status`, `comments`, `revision`, `contentHash` and `planSync` stay. |
| `hive_constraints_read`, `_add`, `_edit`, `_clear` | Entries, revision, joined `constraints` string and `constraintsChars`; cap 8,000 | `{ entries, revision, constraintsChars, maxChars }`, plus `warning` from 8,000 characters; cap 16,000 |
| `hive_feature_select` | The whole session record | `{ sessionId, featureName, startedAt, lastActiveAt, standingConstraintsRevision }` |
| `hive_worklog_read` (`brief` and `history`) | Entries include their `briefing` text | Entries omit `briefing`; an entry that set one carries `briefingUpdated: true`. The brief view's `briefing` field holds the current text once. |
| `hive_explore_update` | The brief view of the exploration | `{ id, status, counts, scopeMapped, stagnantRevisions, lastProgressRevision, committedRevision, currentRevision, replayed }` |

Some consequences for agents and scripts:

- `hive_status` computes `runnable` and `blocked` from every task's full record whatever `detail` is, so the default call is enough for readiness checks. To find the tasks that depend on one, such as before cancelling a task and creating its replacement, call `hive_status({ detail: 'full' })`, because the default call omits `dependsOn` on finished rows.
- A plan outline no longer lists task subsections; read the full plan for them. A plan with more than one `## Tasks` section fails the outline read.
- The constraint `warning` asks the primary to remove entries that applied only to finished tasks or phases. The write that produced it still succeeds.
- Earlier Worklog briefings stay in `worklog.json`, and no read view returns them. `hive_worklog_record` results still return the full stored entry.
- The exploration receipt carries no goal, gaps, observations, authors, timestamps or `untrustedNotice`. Read the `brief` or `full` view with `hive_explore_read` for them.

### Compact JSON

Every Hive JSON result is printed as `JSON.stringify(result)` on both hosts. v6.0.0 indented every result except Worklog and exploration results with two spaces. Named `hive_context_read` chunks measure `maxBytes` against the same compact text, so a chunk of the same budget holds more of the document.

### Removed `hive-core` APIs

`hive-core` is the workspace library bundled into `oc-arkive` and `vscode-arkive`; the release workflow does not publish it. Code built on it loses these unused APIs:

- the prompt-budgeting exports, and `ContextFile.includeInExecution` and `includeInNetwork`;
- the `ContextService` compatibility methods `write`, `list`, `getOverview`, `delete`, `archive`, `stats` and `inspectSummary`, and `getOverviewPath`; `ContextService.read` and the guarded `create`, `replace`, `edit`, `append` and `archiveSelected` methods stay;
- `SubtaskService`, the subtask path helpers, the `Subtask`, `SubtaskStatus`, `SubtaskType` and `TaskAggregateBranchDiff` types, and the `TaskStatus` fields `subtasks` and `aggregateBranchDiff`;
- `SessionContinuityError`, the feature-local `SessionService` methods, the `SessionInfo` fields `duplicatedFromSessionId`, `directivePrompt`, `directiveRecoveryState`, `replayDirectivePending` and `messageCount`, and `SessionsJson.master`.

The [changelog](https://github.com/imarshallwidjaja/agent-hive/blob/v7.0.0/CHANGELOG.md#700---2026-11-27) names each removed `SessionService` method.

## What is new

### Context across v2 compaction

On v2, Hive writes the selected feature route and the verbatim standing constraints to the session's `hive.session` instruction entry. A primary gets the entry when a prompt or fork arrives and again after a route or constraint tool changes them. A child gets it at dispatch, with its bound `Task:` or `Ad-hoc run:` line. The entry survives native compaction and replaces the route footer that v2 dispatch prompts carried; v1 keeps its prompt footer.

For example, a primary that selected feature `checkout-flow` and holds two standing constraints keeps both after OpenCode compacts the conversation. It does not need to call `hive_feature_select` again only because history was compacted. A new Compaction Checkpoint Recovery section tells it to treat the compaction summary as history, re-read only the task, worktree and checkout state its next decision depends on, treat an observed HEAD as unverified rather than as a worker's source pin, and reload any required skill whose text was compacted away. This applies to feature and ad-hoc work. On v2 the execution guidance now sends each next milestone prompt in the same session by default; each prompt still carries its full scope, so a fresh session also works.

Hive also applies the same system parts and tool pruning to `context` and `compaction` requests, so a compaction summarizes under the same rules and shares the turn's prompt prefix. When OpenCode itself shrinks an overflowing compaction, for example by dropping tools, the prefixes can still differ.

### Smaller requests on v2

On ordinary turns and compactions, Hive removes from the request's tool list every tool it refuses the agent for any input: Hive tools the role or session lacks, the native worktree, session and automation tools it guards, and `edit`, `write`, `patch`, `question` or `subagent` when the role or a child session cannot use them. With a broad `"*": "allow"` rule, child sessions no longer receive the schemas of refused tools. A tool refused only for some inputs stays, and a top-level agent Hive does not register keeps every tool. The execution checks still decide each call.

### OpenCode 2.4.2 tool guards

Hive roles, native `general` and `explore`, and every child session cannot run `opencode_session_interrupt` or the four tools that create, resume, pause or delete an automation; listing automations stays native. Hive treats `machine_copy` and `machine_move`, offered under the experimental `machines` flag, as edits, so read-only roles and native `explore` cannot run them. The guard also matches a tool called at top level by its dotted Code Mode name, such as `automation.create`.

### Commands, skills and VS Code

- `/sharpen [prompt or idea]` runs a read-only pass on a candidate prompt and returns one rewritten prompt with a recommended next command. It binds no agent and changes no project files or Hive records.
- The opt-in `black-box-testing` skill covers tests that drive a real consumer interface and assert what it promises. An agent loads it when you ask for a black-box test, ask to adopt, migrate to or audit black-box testing, or work in a repository whose instructions declare a black-box test contract.
- The VS Code **Explorations** view lists active and closed explorations and opens a read-only tab with the goal, frontier targets, observations and their supersedes links. An active exploration's tab follows updates and closure without losing selection, focus or scroll. The tab shows recorded progress only, not whether an agent is still working.
- The VS Code standing-constraints inspector reports usage against 16,000 characters and only peeks at each session index, so opening it no longer backs up and resets a malformed index.

### Other changes

- A bound Forager's task brief names the feature directory once and gives the later paths relative to it.
- `hive_task_update` accepts a `handoff` of up to 4096 UTF-8 bytes, up from 2048.
- A worktree or retained-checkout `finalization` fault carries its recovery rule as `finalization.note`, so tool descriptions and primary prompts are shorter.
- A v2 continuation with a blank, whitespace or bare `ses`/`ses_` `sessionID` is refused before Hive looks up the target.
- A session index that parses but has no `sessions` array, such as `{}` or `null`, is now backed up and replaced like a corrupt index.

## Known limits

- The v2.4.2 evidence is wiring only. The instruction-contract harness wiring run and the credential-free preparation of a supervised exercise passed on stock v2.4.2 with scripted model providers, on a build of commit `5abd2bdc`; that preparation passed 64 of 64 qualification checks. The release commit changes that source only in version fields, documentation and a release test.
- The one live supervised exercise with a real model ran on stock v2.4.1, on commit `81e850f3`, before the move to 2.4.2. It covered compaction prefix parity, the `hive.session` entry after compaction, the slim and `detail: 'full'` status views, the outline shape, the `hive_feature_select` result and the constraint tools. It is a single exercise and is not evidence for 2.4.2 or for other models and providers.
- Rolling back from v7.0.0 to v6.0.0 has not been exercised end to end on either host.
- Neither run is a support claim for other v2 releases. The v1 floor stays 1.18.30, and this release adds no new v1 host evidence.
- When OpenCode shrinks an overflowing compaction, its prompt prefix can differ from the turn's.
- Native locking has been exercised on Linux x64 under Node and Bun only.
- Instruction and skill changes are checked by wording and delivery tests. Those tests do not measure whether a model follows the guidance.

## Release artifacts

The root, `hive-core`, `oc-arkive` and `vscode-arkive` manifests and the generated OpenCode plugin manifest carry version `7.0.0`. Both root lockfiles are regenerated, and OpenCode and VS Code pin local `hive-core` to exact `7.0.0`.

The release workflow publishes `oc-arkive` to npm and attaches `vscode-arkive.vsix` to the GitHub Release, using this file as the release body. The [release guide](https://github.com/imarshallwidjaja/agent-hive/blob/v7.0.0/docs/RELEASING.md) covers preflight, rehearsal and tag-backed recovery.
