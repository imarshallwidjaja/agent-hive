# Agent Hive v5.1.0

Released: 2026-10-27

Agent Hive v5.1.0 adds Worklogs, exact-text context edits, plan sync status and a project-verification skill. It also changes how models are selected: Hive no longer ships a model for any role. This minor version number carries breaking changes, so read [Breaking changes](#breaking-changes) before you upgrade.

The supported hosts have not changed. OpenCode v1 keeps its floor of 1.18.30, and OpenCode v2 is qualified on 2.0.26 only, with no claim about later v2 releases. Each host now registers 41 Hive tools and 13 commands, up from 37 and 11 in v5.0.0.

## Install

**OpenCode v1.** Keep `oc-arkive@latest` in the `plugin` array, or pin `oc-arkive@5.1.0`, and restart the process that hosts the plugin.

**OpenCode v2.** Install the package with npm into a dedicated directory and point the v2 `plugins` entry at its installed `dist` directory:

```bash
mkdir -p /absolute/install
cd /absolute/install
npm install oc-arkive@5.1.0
```

```json
{
  "plugins": [
    { "package": "/absolute/install/node_modules/oc-arkive/dist", "options": { "readTransport": "direct", "server": { "url": "http://127.0.0.1:4096", "passwordEnv": "OPENCODE_SERVER_PASSWORD" } } }
  ],
  "experimental": { "subagent_depth": 2 }
}
```

The [plugin README](https://github.com/imarshallwidjaja/agent-hive/blob/v5.1.0/packages/opencode-hive/README.md#opencode-v2) explains each option, how to start the server and connect the CLI, and how to pack a checkout for contributor use.

## Breaking changes

**Models come from the host unless you configure them.** `DEFAULT_HIVE_CONFIG` has no role models, the starter custom-agent templates name no model or variant, and `hive-core` no longer exports `DEFAULT_AGENT_MODELS`. A built-in role, custom agent or recovery summarizer with no Hive `model` and `variant` uses OpenCode's native model selection. Stored models are kept as written, including values equal to the former generated defaults, so a v1 installation whose `agent_hive.json` was generated earlier keeps every role's old model until you delete that role's `model` and `variant` together.

**A variant needs an explicit Hive model.** An effective `variant` needs a Hive `provider/model-id` from the role's global entry, its project override, or a custom agent's base role. A blank or malformed `model` or `variant`, or a `variant` without that model, stops the plugin at startup with an error that names the file, the property path and the fix. A native OpenCode model does not satisfy the requirement.

**Temperature is gone.** `temperature` is removed from agent, custom-agent and recovery-summarizer settings, the defaults and the schema. A legacy value is ignored with one warning per read, the rest of the file stays valid, and Hive writes omit it. Hive sets no sampling options on either host.

**Recovery follows the caller's model.** Without `taskTraceSummarizer.model`, `hive_task_trace` recovery uses the invoking session's model and variant. A v2 caller without its own model uses the host default with no variant only when that default names a provider package. A configured `model` alone uses that model's default variant, and `variant` requires `model`. When no caller selection can be established, recovery is unavailable.

**v2 refuses a per-call model for Hive agents.** On OpenCode v2, a `subagent()` call that sets `model` for a built-in Hive role or custom agent is refused before the host runs it, even when the value equals the configured model or carries a `#variant`. When the agent has an effective configured model, a same-agent continuation is refused unless the child's session model and variant equal it. An agent with no configured model inherits and its continuations are not checked. Native `general` and `explore`, agents Hive does not register, and model-less inheritance are unchanged.

**`writing-policy` is replaced by `unslop`.** The packaged `writing-policy` skill is removed with no alias. The bundled `unslop` skill is now the shared router for prose, messaging and visual work, and every Hive role and custom agent is asked to load it before covered work. A personal `~/.agents/skills/writing-policy/` is outside the package and is not migrated, so instructions, standing constraints or agent configuration that name `writing-policy` now find only that copy. Add `unslop` to `disableSkills` to remove the bundled skill, or provide a native skill named `unslop` to replace it.

## What is new

### Worklogs

A Worklog is a short account of where work stands: a current briefing and append-only checkpoints that primary agents record at milestones. A feature has one log that every primary session shares, and ad-hoc work keeps a log per native session under its host.

`hive_worklog_list`, `hive_worklog_read` and `hive_worklog_record` are new. `/worklog [request]` reads a log back under the active agent, for example `/worklog what changed on checkout since the plan was approved`; it never records or rewrites the briefing. Reads add recorded task facts computed from stored task records, which say nothing about whether a worker is alive or whether work was verified or integrated. Only primary sessions record, and Hive checks the caller's role and live parent before it writes. Workers and reviewers read.

Log text is agent-written narrative. Hive never injects it into prompts, and agents treat it as information to check. To stop primaries from recording, add a standing constraint such as "Do not keep a Worklog in this session"; reading stays available. The [Worklog contract](https://github.com/imarshallwidjaja/agent-hive/blob/v5.1.0/docs/WORKLOG.md) covers storage, keys and retry behavior.

The VS Code companion gains a **Worklogs** view that reads the log files directly, so logs from finished sessions, cleaned-up worktrees and completed or archived features stay readable without a running host. It shows the selected log, pinned logs and recent logs. **Hive: Open Worklog...** opens any log from a paged list or a full key such as `feature:checkout`. A log opens as a read-only document, and history and recorded facts page ten at a time.

### Exact-text context edits

`hive_context_edit` replaces one exact passage of an existing context file and keeps every other byte, including a BOM, CRLF and Unicode. It needs the revision and whole-file `contentHash` from a named read. That read has to show the passage with enough surrounding text, and `oldText` has to occur exactly once. A validation refusal before publication writes nothing; publication errors can leave the document or index uncertain. After an error or unknown result, read the document and confirm whether the edit applied before retrying. On `context_index_invalid` or `context_reconciliation_required`, stop managed mutations and report the error. Roles that can write context have it; Scout stays read-only.

### Plan sync status and selected task refresh

`hive_plan_read`, `hive_plan_write`, `hive_plan_patch`, `hive_plan_approve`, `hive_tasks_sync` and `hive_status` now carry an advisory `planSync` of `current`, `changed`, `incomplete` or `unknown`. It is computed on read from the per-feature `task-sync.json` and the current task files. It writes nothing and never approves, syncs or blocks.

`hive_plan_approve` returns the approved `contentHash` and binds its sync to it. A hash mismatch checked before sync writes blocks task writes, but approval may already have persisted. If approval is superseded during sync, task writes may already have succeeded or partially applied. Before retrying, inspect the separate approval and sync outcomes, `approvalPersisted` and sync progress; see the [plan management contract](https://github.com/imarshallwidjaja/agent-hive/blob/v5.1.0/packages/opencode-hive/docs/HIVE-TOOLS.md#plan-management-4-tools). The tool also accepts `refreshTasks` to apply an amended plan to started plan tasks once the primary has confirmed that no assignment for them is running. A Forager's task brief shows a `Plan sync <state>: <hint>` line when the state is not `current`.

Plan tasks now state a Goal, the Responsibility they own, References with the reason for each, and Verify, in place of a predicted file list. Exact paths appear only where a sibling task or a public contract needs them.

Task sync also protects history. It no longer deletes a pending plan task that is missing from the plan when the task has a recorded start, a report or a handoff; the sync is rejected, and you restore the heading or cancel the task with `hive_task_update` to keep it as a retained record. It never recreates a plan task folder whose `status.json` is missing and never renames a folder. It never creates a new folder for a heading number whose earlier folder holds started or finished work, which is what retitling that heading would do.

### Project verification

Setting up, auditing or maintaining a project's durable verification capability has its own packaged skill, `project-verification`. Agents are instructed to load it when you or an assignment ask for that work, for example "Audit our verification guide against the current CLI and report drift." Ordinary feature tests, fixtures and diagnostic probes stay part of implementation or diagnosis.

When the choice of checks is open, `verification` reads the candidate's applicable `AGENTS.md` for concise verification guidance or a scoped pointer to a detailed guide. Hive prescribes no location, filename, heading or format for that guide, and a pointer that is missing or does not cover its scope is reported as a guidance defect rather than searched for. Guidance describes method and never adds or drops a required gate. Changing an `AGENTS.md` entry stays an instruction change that you approve item by item. A verify-only assignment changes no candidate source, test, fixture, snapshot or gate and commits nothing.

### Commands, skills and review

- `/implement` runs under the agent and model already selected on both hosts. Everything typed after it, multiline prose included, reaches the agent unchanged as further context and steering. It does not create a feature, plan or task by itself, and approved feature plans still run through `/start-execution`.
- `/grill` and `/interview` research the supplied context before asking, explain evidence and tradeoffs, and keep your choices even when a recommendation is confident. `/grill` ends in plan-ready alignment that can go to `/hive-plan`; `/interview` has a flexible endpoint.
- A feature plan needs `plan-reviewer` and `approach-advisor` assessments of the same plan `contentHash` before approval. Later changes reassess only the lens they affect, and the approval tools are unchanged.
- `dash-reviewer` and `vulnerability-review-primary` can send the built-in Forager, or a configured derivative, on a report-only diagnosis to run the candidate along its intended journeys. Foragers are never required reviewers, and specialist reviewers stay non-executing.
- The bundled `stop-design-slop` skill carries composition, diagnostics and refinement guidance and a contrast checker, with provenance and license notices in its `UPSTREAM.md` and license files.
- Workflow skills moved examples and milestone procedures into packaged `references/` files, and `humanizer` audits an agent's own draft before delivery.

### Fixes

- The v1 `chat.message` hook sets the Hive variant on `message.model.variant`, as OpenCode 1.18.30 reads it, and only fills a missing variant when the message runs the agent's own Hive model.
- The v2 entry no longer adds a role temperature to ordinary, compaction and generate requests, and a malformed configured model fails registration instead of being dropped.

The [changelog](https://github.com/imarshallwidjaja/agent-hive/blob/v5.1.0/CHANGELOG.md#510---2026-10-27) lists every change in detail.

## Upgrade from v5.0.0

1. Finish or deliberately abandon live workers in the current host.
2. Review `~/.config/opencode/agent_hive.json`. Check that every `variant` has an explicit Hive `model` for the same role, delete any `temperature`, and delete a role's `model` and `variant` together if you want it to inherit the host's selection. Hive reads this file from `HOME`, not from `XDG_CONFIG_HOME`.
3. On v2, remove any `model` argument from `subagent()` calls that target a Hive role or custom agent.
4. On v1, update the plugin entry to `oc-arkive@5.1.0` or refresh the cached `@latest` package. On v2, install the package as shown above.
5. Restart the long-lived process that loaded the plugin, such as an `opencode` TUI, an `opencode serve` process, or a service that runs one. A restart reloads whatever the configuration points at, so update the package first. Restarting a client attached to a server does not reload the server's plugin.
6. Send a new message in each session before using Hive-governed tools, and launch fresh child sessions.
7. Replace references to `writing-policy` in your own instructions with `unslop`.
8. Install `vscode-arkive.vsix` from the v5.1.0 GitHub Release with `code --install-extension ./vscode-arkive.vsix`.

The [Operator Guide](https://github.com/imarshallwidjaja/agent-hive/blob/v5.1.0/docs/OPERATOR-GUIDE.md#upgrade) has the full upgrade notes, including the model rules in [Agent models](https://github.com/imarshallwidjaja/agent-hive/blob/v5.1.0/packages/opencode-hive/README.md#agent-models).

## Known limits

- The v2 qualification covers 2.0.26 only. It is not a support claim for later v2 releases.
- The v2 managed-subagent model controls were exercised with credential-free probes on stock v2.0.26, and the instruction changes were checked in bounded supervised exercises whose evidence collector clips oversized records. These results establish wiring, recorded effects and the behavior of the named runs. They do not show equivalent behavior across live models or providers. Check the models that actually run, including recovery models.
- The limits listed for v5.0.0 still apply to v2, including that a top-level session uses the explicit CLI/session model or the native configured model rather than its agent's registered model.
