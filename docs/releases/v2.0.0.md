# Agent Hive v2.0.0

Agent Hive v2.0.0 removes project-local runtime configuration, adds isolated multi-model dash reviews, and makes delegation and merge history contracts explicit.

## Breaking Change

- Agent Hive now reads runtime configuration only from `~/.config/opencode/agent_hive.json`.
- Project-local `.hive/agent-hive.json` and legacy `.opencode/agent_hive.json` files are ignored, including malformed files. They are no longer overlays or fallbacks.
- Before upgrading, move active sandbox, agent, MCP, hook cadence, custom-agent, skill, and repository settings into the global file.
- A global `repositories` manifest must include an absolute `repositoryRoot` that resolves to the same checkout as the active OpenCode project root. Repository entry paths stay relative to `repositoryRoot` and cannot escape it. A manifest whose root does not match the active checkout remains inactive.

Example scoped manifest:

```json
{
  "repositoryRoot": "/absolute/path/to/project",
  "repositories": [
    { "id": "api", "path": "./api" },
    { "id": "web-ui", "path": "./apps/web-ui" }
  ]
}
```

## Added

- `/dash-review [scope]` runs an orchestrated, findings-only review against one frozen disposable workspace without changing implementation source.
- Single-repository reviews use a detached worktree. Composite reviews materialize each selected manifest repository under `repos/<repoId>/`. Dirty captures preserve final file bytes, modes, symlinks, additions, deletions, and renames.
- Source identity is checked before synthesis. Drift, truncation, missing repositories, or incomplete cleanup produces `NEEDS_DISCUSSION` rather than an approval.
- Eligible scout, code-review, and simplicity-review sources become isolated review lanes that preserve their model, variant, review lens, and skill guidance while denying task recursion and Hive lifecycle mutations.

## Changed

- Each native `task()` launch now represents one primary goal, one fresh subagent session, and one terminal handoff. Returned task IDs are observe-only handles for status, reconciliation, and cancellation; they are not session-resume inputs.
- Blocked feature work continues in the same worktree through a new worker session with the operator decision. Failed or retry work starts a fresh worker with a self-contained handoff. Completed, failed, and blocked sessions do not receive follow-up prompts.
- When `hive_merge` or ad-hoc merge omits a merge or squash message, Hive derives a project-readable message from source branch commits and reports `commitMessage` and `messageSource`. Operators can still provide an explicit merge or squash message. Rebase does not accept a custom message.
- Primary-agent guidance now treats delegation as the baseline for non-trivial work. Background mode changes wait behavior and board protocol; it does not define whether work should be delegated.
- Numbered plan tasks describe worker-branch units rather than individual test, implementation, and commit steps.
- Brainstorming keeps validated designs in the current session unless the user or repository workflow explicitly requires a tracked document.
- The VS Code Tracked Repositories view reads the global manifest only when `repositoryRoot` matches the open workspace.

## Fixed

- XML background-task parsing reads terminal state from the opening `<task>` tag, supports either `id`/`state` attribute order, and no longer treats `status:` prose inside `<task_result>` as runtime state.
- Dash review command internals no longer expose the private review primary as a public agent or add review-only tools to `hive-master`.
- Orchestration guidance no longer fragments one implementation assignment into micro-tasks or conflates background execution with delegation.
