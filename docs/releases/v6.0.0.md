# Agent Hive v6.0.0

Released: 2026-11-22

Agent Hive v6.0.0 moves the OpenCode v2 entry to OpenCode 2.3.2 and replaces the persisted background board with live child status and cancellation on v2. It adds councils resolved through `hive_councils_list`, Exploration frontiers, and nine v2 Code Mode reads grouped under one `hive` namespace. The release is a major version because it removes two tools and one command, drops council cap and exclusion settings, and no longer supports OpenCode v2 2.0.26.

Both host entries remain in the one `oc-arkive` package. OpenCode v1 keeps its floor of 1.18.30. OpenCode v2 is qualified on 2.3.2 only. Each host now registers 50 Hive tools and 17 commands, compared with 49 and 18 in v5.3.0. The VS Code companion still requires VS Code 1.67.0 or later.

## Install and upgrade

These steps upgrade from v5.3.0. From a release before v5.2.0, install v6.0.0 directly and also follow the lock and recovery procedure in the [Operator Guide](https://github.com/imarshallwidjaja/agent-hive/blob/v6.0.0/docs/OPERATOR-GUIDE.md#upgrade).

1. Finish or abandon live workers on the hosts you are upgrading.
2. On OpenCode v1, set the plugin entry to `oc-arkive@6.0.0`, or refresh the cached `@latest` package.
3. On OpenCode v2, plan the host upgrade first. OpenCode 2.3.2 migrates the native database on its first start, and 2.0.26 cannot read the migrated database. Quiesce and stop the 2.0.26 host and keep a copy of its native home, as described in [Switching OpenCode hosts and rollback](https://github.com/imarshallwidjaja/agent-hive/blob/v6.0.0/docs/OPERATOR-GUIDE.md#switching-opencode-hosts-and-rollback). Then upgrade the host to 2.3.2 and install this version into the dedicated directory that its `plugins` entry points at:

   ```bash
   cd /absolute/install
   npm install oc-arkive@6.0.0
   ```

   Keep `plugins` pointed at the installed `dist` directory; 2.3.2 refuses a file path there. A v2 host that stays on 2.0.26 keeps `oc-arkive@5.3.0`. The [plugin README](https://github.com/imarshallwidjaja/agent-hive/blob/v6.0.0/packages/opencode-hive/README.md#opencode-v2) covers v2 options, the session reader and host setup.
4. Install `vscode-arkive.vsix` from this GitHub Release with `code --install-extension ./vscode-arkive.vsix`.
5. Remove `hive_background_reconcile`, `hive_background_reconcile_batch` and `/council-directive` from custom instructions and scripts. To get a draft council directive, ask for one in prose.
6. Update your council configuration in `~/.config/opencode/agent_hive.json`. `council.maxMembers`, `council.groups.<name>.maxMembers` and `council.excludedAgents` are now ignored, so every usable seat a group lists runs. To keep a seat out, remove it from that group's `members`, or override a built-in group under `council.groups.<name>`.
7. On OpenCode v1, remove `disable: true` from any Hive subagent you still want to use. Hive now keeps that setting instead of overwriting it.
8. On OpenCode v2, give agents a working session reader if they continue children with `sessionID`. Without the `server` option, Hive uses the managed local service when its registration names the OpenCode process that loaded the plugin and a numeric loopback URL, as with `opencode serve --service`. Any other host process needs the `server` option in its `plugins` entry.
9. Restart the long-lived host process that loads the plugin, such as the `opencode` TUI, `opencode serve`, or its service. Restarting an attached client does not reload the server's plugin.
10. After the restart, send a new message in each session before using Hive tools, and launch fresh child sessions. Before the first council, ask a primary agent to call `hive_councils_list` and check the resolved roster.

Existing plans, tasks, context, Worklogs and worker state are read as before, and no migration flag is required. Hive no longer reads the `background-jobs.json` files earlier releases left, and it does not delete them.

## Breaking changes

### OpenCode v2 2.3.2

The v2 entry builds against `@opencode/plugin` and `@opencode/client` 2.3.2 and Effect 4.1.0, and it takes tool errors, model references and provider IDs from the host's `@opencode/plugin/effect`. `oc-arkive@5.3.0` fails to activate on 2.3.2, and v6.0.0 does not support 2.0.26. The `effect` peer range is now `>=4.1.0 <5`.

On 2.3.2 every `subagent()` call runs in the background and returns a launch receipt. The host posts a report each time the child stops: `state="running"` is interim, and `completed`, `error` and `cancelled` are terminal. Agents wait for the terminal report before relying on a result.

### Live child status replaces the background board

`hive_background_reconcile` and `hive_background_reconcile_batch` are removed, and Hive no longer writes `background-jobs.json`. On v2, `hive_background_status` lists the calling session's direct children that still have work running, or reads whether one child's whole session tree has settled. `hive_background_cancel` interrupts one child's active execution; shell commands and descendant jobs the child already moved to the background keep running. Neither tool records anything. On v1 both return `unsupported_on_host`, because v1 `task()` calls block. The `OPENCODE_EXPERIMENTAL_BACKGROUND_SUBAGENTS` gate, the v1 background appendix, the `background-delegation` skill and the VS Code **Background Jobs** view are removed. The **Repositories & Work** view shows each worker's recorded sessions instead.

### Councils and `/council-directive`

Council resolution runs every usable seat a group lists and has no fallback. An unknown council, or one with no usable seat, is an error and launches nobody. The cap and exclusion settings are ignored; files that still set them load and validate, and the JSON schema marks them deprecated. `/council-directive` is removed, so each host registers 17 commands.

## What is new

### Councils

`hive_councils_list({ name? })` resolves one council, the named one or the configured default, and reports the selected seats and the skipped seats with their reasons. It dispatches nobody. Six Hive primaries hold it, and it is refused in every child session, so a subagent returns a council request to its parent. The packaged `council` skill owns the procedure: draft a directive, decide who can convene, resolve the council, brief the seats read-only and synthesize. `/council` is a thin entry to that skill. A seat derives from one of six base roles, now including `vulnerability-reviewer`. The convenor and every seat work read-only by instruction; the host does not sandbox them.

### Exploration frontiers

`hive_explore_read` and `hive_explore_update` record one investigation in any domain under `.hive/explorations/`. An exploration holds a goal, a keyed frontier of targets with states `open`, `covered`, `blocked` or `dropped`, and keyed observations with status `confirmed`, `hypothesis` or `refuted`. Updates are revision-guarded, and an `operationId` makes a retry return `replayed: true`. Every Hive role can read explorations; only primary sessions can update them. Exploration entries are agent-recorded notes, not verified results.

### Grouped Code Mode reads on v2

Under the default `readTransport: "codemode"`, nine reads run inside Code Mode under one namespace, `hive`: `hive_repositories_status`, `hive_repositories_discover`, `hive_git_snapshot`, `hive_task_trace_content`, `hive_worklog_list`, `hive_worklog_read`, `hive_checkouts_list`, `hive_checkout_brief` and `hive_explore_read`. Code calls them as `tools.hive.<name>`, such as `tools.hive.checkout_brief`, so one script can chain reads and return only the result it needs. The host joins the namespace and local name back into the same `hive_*` tool ID, so permissions, role grants and the execution guard are unchanged. All other Hive tools stay direct calls, including the live child tools, `hive_worklog_record` and `hive_explore_update`. `readTransport: "direct"` still makes every Hive tool a direct call. v1 is unchanged.

### Continuations, automations and reader setup on v2

A `sessionID` continuation is allowed only for a settled child of a resumable role (`forager-worker`, `forager-investigator`, `architect-planner` and agents derived from them, plus native `general` and unmanaged agents), on the agent the child already runs. Hive refuses a continuation while the child's session tree still shows work or while that state cannot be read. Hive roles, native `general` and `explore`, and every child session are refused the four OpenCode automation tools that create, resume, pause or delete an automation; listing automations stays native. Without the `server` option, Hive's session reader uses the managed local service when it can confirm that service is the process that loaded the plugin.

### Reviews and guidance

- `/vuln-review` and its `vulnerability-reviewer` specialists load the packaged `security-audit` skill. A review maps entry points, trust boundaries and shared defenses, sends specialists in waves, keeps a broad audit's progress in an Exploration frontier, challenges each material candidate in a fresh session and sweeps each surviving root cause for siblings. The review stays source-first and read-only; a local simulated pentest runs only when you ask for one, against a disposable local instance bound to loopback.
- `dash-reviewer` and `vulnerability-review-primary` accept `model`, `variant` and `autoLoadSkills` in `agent_hive.json`. Without those settings they behave as before.
- Implementing workers record a behavior break when they add or change a behavior test, and list each existing caller's check when they narrow a contract. The merging primary holds a merge on caller checks that have not run.
- The `architect-planner` task permission now allows code, simplicity and vulnerability reviewers, which its instructions use only as seats of a council a primary Architect convenes.
- Engineering guidance limits test seams to natural boundaries, reshapes a shared helper together with its callers when every affected caller is in scope, and keeps coherent functions and files intact.

### Fixes

- Hive resolves an agent's model and variant as a pair at each configuration layer, so a layer that changes the model no longer keeps a variant chosen for another model.
- On v1, Hive keeps `disable: true` for the subagents it registers.
- The council synthesis counts agreement only among seats that gave a recommendation.

## Known limits

- Host wiring qualification ran on stock v1.18.30 and v2.3.2 with scripted model providers. It ran on a build of commit `f3481a79`, whose tree is identical to `4a5b3829` and whose manifests still said 5.3.0. On the installed hosts it checked registration, schemas and v2 Code Mode discovery of the 50 tools, the listing of the 17 commands, selected context and repository operations, the `/start-execution` command, and model and skill wiring. It does not exercise every tool and command at runtime, and it establishes wiring, not real-model judgment.
- On v2, a native allow rule that applies after Hive's default permission rules, such as a global `"*": "allow"`, makes more Hive tools visible to an agent, including a grouped `hive` read its role is not granted. The Code Mode catalog and `search({ namespace: "hive" })` then list that read, and Hive's role guard still refuses the call. With stock permissions, or with an exact native deny for that agent, the restricted read stays hidden. A live v2 session on the operator's host showed this for an Investigator and `hive_repositories_discover`.
- Native locking has been exercised on Linux x64 under Node and Bun only.
- Instruction and skill changes are checked by wording and delivery tests. This release makes no new cross-model or cross-provider claim that models follow them.

## Release artifacts

The root, `hive-core`, `oc-arkive` and `vscode-arkive` manifests and the generated OpenCode plugin manifest carry version `6.0.0`. Both root lockfiles are regenerated, and OpenCode and VS Code pin local `hive-core` to exact `6.0.0`.

The release workflow publishes `oc-arkive` to npm and attaches `vscode-arkive.vsix` to the GitHub Release, using this file as the release body. The [release guide](https://github.com/imarshallwidjaja/agent-hive/blob/v6.0.0/docs/RELEASING.md) covers preflight, rehearsal and tag-backed recovery.
