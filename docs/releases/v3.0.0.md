# Agent Hive v3.0.0

Released: 2026-10-01

Agent Hive v3.0.0 replaces managed execution attempts with direct worktree operations, worker-owned commits, and immutable task reports. It also makes feature routing explicit, adds project and feature context retrieval, and changes forensic session traces to a paged index. This is a breaking upgrade from v2.5.0; review the migration steps before restarting the plugin host.

## Breaking changes

- OpenCode >= 1.18.30 is required, up from >= 1.14.48 in v2.5.0. Upgrade the OpenCode host before updating the plugin.
- Execution uses `hive_worktree_create`, native `task()` dispatch, a worker Git commit, and `hive_worktree_merge`; the ad-hoc lifecycle uses the corresponding `hive_adhoc_worktree_*` tools. The retired start, commit, discard, and merge tools and private review workspace tools are listed in the [changelog](https://github.com/imarshallwidjaja/agent-hive/blob/v3.0.0/CHANGELOG.md#removed). Task status and reports are recorded through `hive_task_update`. Plans and dependencies guide execution; they are not runtime dispatch admission gates.
- Merge calls require the worker's exact source pin and the caller's inspected destination identity. Destination movement requires inspection and reconciliation before integration.
- Hive no longer wraps worktree bash commands in Docker, recognizes the `HOST:` prefix, or bundles the `docker-mastery` skill. Commands run through the host's exposed tools and permissions.
- `oc-arkive` no longer installs or configures research MCP servers or bundles the provider-specific structural-search skill. Operators configure needed research integrations through OpenCode or other installed integrations.
- Non-recovery `hive_task_trace` returns a paged forensic v3 index of surviving non-reasoning events. Full tool input, output, and error are retrieved through guarded `hive_task_trace_content` event selectors. Recovery remains untrusted context and does not authorize resuming a child or accepting its work.
- `hive_git_snapshot` always returns a `hive-git-snapshot/v1` envelope, replacing the old bare or composite result. Check `status === 'ready'` before reading `snapshots[n].snapshot`; failed captures return `failures`.

## Added and changed

- `hive_feature_select` explicitly controls the session's feature route, including an explicit null route. Feature targets on individual calls are call-local. Both session and selected-feature constraints travel with delegated assignments.
- `.hive/agent-hive.override.json` can override `model` and `variant` for matching built-in and configured custom agents. Other runtime settings remain in `~/.config/opencode/agent_hive.json`.
- Scoped project and feature context catalogs support bounded reads and revision/hash-guarded mutations. Workers retrieve relevant context explicitly. Durable context guidelines produce hygiene warnings rather than rejecting growth; every managed document has a 1 MiB limit.
- Task updates retain immutable numbered report history and can publish a bounded successor `handoff.md`. Status exposes task spec freshness and handoff presence. A bound Forager dispatch receives a path-only brief when its first non-empty assignment line is `Hive task: <task-folder>`.
- VS Code browses scoped context and numeric task report history, and supports scoped context archival.
- Packaged engineering, explanation, writing, complexity, and ad-hoc orchestration skills give agents focused guidance. Review instructions require understanding the affected contract and independently challenging material findings. Planning guidance supports DAG-backed execution milestones.
- Task sync and spec freshness handle CRLF plans and zero-padded task headings. Plan approval returns an explicit result, interrupted background jobs can be observed through child events, and safe merges can retain disjoint untracked destination files.

## Upgrade from v2.5.0

1. Finish or explicitly abandon live workers before upgrading. Keep the existing plans, tasks, context, reports, and workspace files; old attempt and lease files remain unread.
2. Upgrade the OpenCode host to >= 1.18.30 before updating `oc-arkive`.
3. Edit `~/.config/opencode/agent_hive.json` and remove `disableMcps`, `sandbox`, `dockerImage`, and `persistentContainers`. Strict validation rejects these keys. While any remain, Hive ignores the whole global configuration, including agent model overrides and custom agents. In projects without `.hive/repositories.json` or a generated `workspace.json`, including ordinary single-root repositories, repository and worktree tools also fail with an invalid-config error that names the file but not the key. Rename custom-agent IDs containing `*` or `?` and update references. `hook_cadence` remains accepted as a map of positive integers, but no production hook currently invokes its gate; it has no runtime effect.
4. Update copied agent instructions and scripts:
   - Replace `hive_worktree_start` with `hive_worktree_create` followed by native `task()` dispatch. Create no longer updates task state or accepts `continueFrom`/`decision`. To continue a blocked task, use `hive_task_update` with an explicit status leaving blocked, then dispatch a fresh native `task()` with the operator decision in its prompt.
   - Remove `autoSpawnWorker`/`workerInstructions` from `hive_adhoc_worktree_create` calls. Create no longer prepares a worker launch; explicitly dispatch native `task()` after creating the ad-hoc worktree.
   - Replace `hive_worktree_commit` and `hive_adhoc_worktree_commit` with a worker-owned Git commit. Inspect the worktree and pass its exact `sourceCommit` for a legacy single-root workspace, or complete `sourceCommits` map for declared repositories, to `hive_worktree_merge` or `hive_adhoc_worktree_merge`. Supply the inspected `expectedTarget` or complete `expectedTargets` unchanged. Use the matching cleanup tool after integration.
   - Replace `hive_merge` with `hive_worktree_merge`, `hive_adhoc_merge` with `hive_adhoc_worktree_merge`, and `hive_adhoc_cleanup` with `hive_adhoc_worktree_cleanup`. Replace `hive_worktree_discard` with `hive_worktree_cleanup({ discard: true })` only when intentionally discarding unintegrated work; use cleanup without `discard: true` after successful integration.
   - Use `hive_task_update` for status, immutable reports, and successor handoffs; use `/dash-review` and `/vuln-review` for reviews. Remove references to all retired tools listed in the changelog.
   - Replace `verification-before-completion` and `verification-reviewer` in copied skill instructions and `autoLoadSkills` entries with `verification`: Completion Gate Mode for completion checks, Verification Report Mode for independent verification. Remove `code-reviewer` skill loads and `autoLoadSkills` entries; dispatch the `code-reviewer` subagent for implementation reviews.
   - Select the feature with `hive_feature_select` before delegation. A returned native task result ends that child invocation; launch a fresh child for follow-up work unless an explicit operator instruction or runtime-owned interruption recovery authorizes continuation.
   - Call `hive_context_read` before replacing, appending, or archiving existing context. Map the returned `revision` to `expectedRevision` and `file.contentHash` to `expectedContentHash` for replacement/append; archive requires `expectedRevision` and per-name `expectedContentHashes`. Named reads default to 16 KiB chunks, but the hash covers the entire file. Follow `nextCursor` as `cursor` until `complete: true` and reconstruct the full document before whole-document replacement; writing only the first chunk would truncate it despite a valid hash.
   - Update forensic trace consumers to follow `coverage.next_cursor` and select `events[n].ref` with `hive_task_trace_content`. Continue oversized fields with the same `event` and `field`, setting the request's `offset` to the prior response's `next_offset`. Re-index after a stale cursor or changed event.
   - Update snapshot consumers to check `status === 'ready'` and read `snapshots[n].snapshot` from the `hive-git-snapshot/v1` envelope.
5. Configure the research tools you need through your OpenCode integrations. Remove reliance on Hive's Docker wrapping and `HOST:` prefix from local workflows.
6. Update the OpenCode plugin entry to `oc-arkive@3.0.0`. Update a cached plugin package if your installation uses one. For the VS Code companion, download `vscode-arkive.vsix` from the v3.0.0 GitHub Release and install it with `code --install-extension ./vscode-arkive.vsix`.
7. Restart the process that hosts the plugin after updating. For a standalone CLI, quit and relaunch OpenCode. For a server installation, restart the long-lived server process; if managed by `opencode.service`, restart that service. After restarting, send a new message in the session so the runtime observes its agent again before using Hive-governed tools. Reload VS Code after installing the companion. Hive does not overwrite user-authored global settings or stale copied workflow instructions.

See the [operator guide](https://github.com/imarshallwidjaja/agent-hive/blob/v3.0.0/docs/OPERATOR-GUIDE.md), [tool reference](https://github.com/imarshallwidjaja/agent-hive/blob/v3.0.0/packages/opencode-hive/docs/HIVE-TOOLS.md), and [configuration schema](https://github.com/imarshallwidjaja/agent-hive/blob/v3.0.0/packages/opencode-hive/schema/agent_hive.schema.json) for current contracts.

## Release artifacts

- Root, `hive-core`, `oc-arkive`, and `vscode-arkive` manifests, both root lockfiles, and the generated OpenCode plugin manifest carry version `3.0.0`. The two `hive-core` dependency pins are exact; local development links to the workspace package.
- The release workflow publishes `oc-arkive` to npm through Trusted Publishing and attaches `vscode-arkive.vsix` to the GitHub Release using this file as its body. A manual rehearsal builds and tests without publishing. Follow [release preparation and recovery](https://github.com/imarshallwidjaja/agent-hive/blob/v3.0.0/docs/RELEASING.md) for rehearsal-before-tagging and selective recovery from an existing tag.
