# Agent Hive v2.3.1

Agent Hive v2.3.1 makes newly registered repository topology available to frozen reviews without an OpenCode restart and moves npm publication to OIDC trusted publishing.

## Changed

- The release workflow publishes `oc-arkive` through npm Trusted Publishing with GitHub Actions OIDC instead of a static `NPM_KEY` token. The job uses Node 24 and npm 11.5+, keeps the anonymous already-published check, and receives provenance from Trusted Publishing.

## Fixed

- After `hive_repositories_update` adds a repository at a non-Git project root, authorized `hive_git_snapshot` and `hive_review_workspace_create` calls resolve the updated project-local manifest in the same session. Nested repository paths containing spaces are supported, while review authorization and manifest path, containment, canonicalization, and symlink checks remain enforced.

## Upgrade

- Update `oc-arkive` to `2.3.1` through the normal OpenCode plugin installation flow.
- No Agent Hive configuration or project-local repository-manifest migration is required.
- Fork maintainers who publish `oc-arkive` must configure the npm trusted publisher described in `docs/RELEASING.md`. After the first OIDC publish succeeds, remove the `NPM_KEY` repository secret and revoke the old npm automation token.

## Release

- Tagged `v2.3.1` pushes publish `oc-arkive` to npm through Trusted Publishing, attach `vscode-arkive.vsix` to the GitHub Release, and use this file as the release body.
