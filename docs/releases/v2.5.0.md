# Agent Hive v2.5.0

Agent Hive v2.5.0 turns feature context into a managed, revisioned lifecycle, replaces the whole-register constraint write with targeted entry operations, and makes failed delegated work inspectable before an orchestrator relaunches it.

## Added

- Managed feature context: `context/index.json` revisions every mutation, and `hive_context_read`, `hive_context_append`, and `hive_context_archive` join `hive_context_write`. Non-reserved documents classify as `durable` (injected into worker and network prompts) or `evidence` (available to explicit reads, excluded from prompts). Recommended caps are 8 durable files and 40,000 durable characters; legacy over-cap features stay readable but cannot increase either over-cap dimension. `overview`, `draft`, and `execution-decisions` remain reserved and uncapped.
- Session lineage: `SessionInfo` records `parentSessionId` and `duplicatedFromSessionId`, and a duplicated root session carries its standing constraints, session kind, and feature association across.
- Arkive context and constraint inspection: the Features view shows context classifications, sizes, inclusion policy, and durable budgets; **Archive Context** archives confirmed documents against a captured revision with a required reason; **Hive: Inspect Session Standing Constraints** opens a read-only document for an explicitly selected session.

## Changed

- `hive_constraints_set` is replaced by `hive_constraints_read`, `hive_constraints_add`, `hive_constraints_edit`, and `hive_constraints_clear`. Entries carry stable IDs, edit and clear reject stale revisions atomically, identical additions are idempotent, and the aggregate cap is 8000 UTF-16 code units. Existing register text is preserved.
- Scouts retrieve bounded source-grounded evidence and no longer own diagnosis, correctness judgement, tradeoff analysis, or solution selection. Diagnosis-only Forager missions report evidence, tested and untested hypotheses, and requested options without editing, committing, or running destructive reproduction.

## Fixed

- Native child sessions associate with the exact Hive task attempt that spawned them across blocking and background paths, so `hive_task_trace` surfaces failed or unclear delegated work rather than leaving the orchestrator to guess before relaunching.
- `hive-master`, `swarm-orchestrator`, and `hive-builder` are registered as primary-only and reject native `task()` dispatch targeting them. Architect keeps its bounded read-only child delegation exception.

## Upgrade

- Update `oc-arkive` to `2.5.0` through the normal OpenCode plugin installation flow.
- Replace `hive_constraints_set` calls in operator-local agent definitions or scripts with `hive_constraints_add`, and use `hive_constraints_read` plus `hive_constraints_edit` for corrections.
- Existing feature context directories are read without migration. The first managed mutation writes `context/index.json`.
- Restart OpenCode after updating so config-time plugin and guidance changes take effect. If OpenCode uses a cached plugin package, update that cached package before restarting.

## Release

- Tagged `v2.5.0` pushes publish `oc-arkive` to npm through Trusted Publishing, attach `vscode-arkive.vsix` to the GitHub Release, and use this file as the release body.
- Release artifacts carry version `2.5.0` across the root, `hive-core`, `oc-arkive`, and `vscode-arkive` manifests, both lockfiles, and the generated OpenCode plugin manifest.
