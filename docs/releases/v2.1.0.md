# Agent Hive v2.1.0

Agent Hive v2.1.0 moves repository topology to a project-local manifest and improves scout exploration defaults for primaries.

## Added

- Repository topology now persists per project in `.hive/repositories.json`. Entry paths are relative to the canonical project root and cannot escape it.
- `hive_repositories_update` migrates matching legacy global topology into the project manifest and removes only the migrated legacy keys while preserving other global preferences.

## Changed

- Legacy global `repositoryRoot` and `repositories` fields remain accepted only as migration input. Active runtime reads use the project-local manifest.
- Universal metadata tools `hive_repositories_status`, `hive_plan_read`, and `hive_status` are available to Hive Builder, Forager, Scout, and Hygienic in addition to the primary orchestration agents.
- Primary agents now auto-load `parallel-exploration` alongside `verification`.
- Scout parallel exploration guidance no longer caps research fan-out by question count. Breadth and multi-domain scope are decomposition signals, not capable/custom Scout selection signals.

## Fixed

- Config writes preserve sparse user config instead of expanding omitted defaults into the global file.
- Scout capability routing stays bounded to researcher selection after parallel-exploration decomposition.

## Upgrade

- If you still keep repository topology in `~/.config/opencode/agent_hive.json`, run `hive_repositories_update` in the target project to migrate it into `.hive/repositories.json`.
- No other config migration is required for sandbox, agent, MCP, hook cadence, custom-agent, or skill settings.

## Release

- Tagged `v2.1.0` pushes publish `oc-arkive` to npm, attach `vscode-arkive.vsix` to the GitHub Release, and use this file as the release body.
