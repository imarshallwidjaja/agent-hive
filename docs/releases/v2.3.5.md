# Agent Hive v2.3.5

Agent Hive v2.3.5 adds shared human-centered Engineering Judgment and contextual testing guidance, makes feature selection follow the caller's actual context, and removes hidden project-global active-feature state.

## Added

- Architect, Hive, Forager, and ordinary reviewers now share Engineering Judgment guidance for designing from call sites, keeping risk-bearing policy visible, choosing cohesive module boundaries, generalizing only from demonstrated variation, and removing abstractions or fallbacks that carry no current responsibility.
- Testing guidance now chooses the strategy that fits the work: public-contract behavior tests, characterization tests for uncertain behavior, tests alongside or after implementation, existing coverage for pure refactors, or proportionate non-test checks. Forager still verifies its work without automatically applying test-driven development to every task.

## Changed

- Feature resolution now follows explicit feature input first, then worktree or task context, canonical session ownership, and finally the sole live feature. When multiple live features exist and none of those sources identifies one, callers must pass or select the feature explicitly.
- Planning, implementation, debugging, and review guidance now evaluates design and verification in context rather than imposing one universal abstraction or testing workflow.

## Fixed

- Hidden project-global `.hive/active-feature` selection has been removed. Feature operations no longer depend on mutable checkout-wide selection that can conflict with session or worktree ownership.
- The VS Code feature view no longer highlights or orders features using hidden active-feature state. Feature display follows the persisted feature data without implying a project-global selection.

## Upgrade

- Update `oc-arkive` to `2.3.5` through the normal OpenCode plugin installation flow.
- When a project has multiple live features, pass or select the intended feature explicitly unless the current worktree, task, or canonical session already identifies it.
- No Agent Hive configuration, feature data, or project-local repository-manifest migration is required. Existing `.hive/active-feature` files are no longer consulted.
- Restart OpenCode after updating so config-time plugin and guidance changes take effect. If OpenCode uses a cached plugin package, update that cached package before restarting.

## Release

- Tagged `v2.3.5` pushes publish `oc-arkive` to npm through Trusted Publishing, attach `vscode-arkive.vsix` to the GitHub Release, and use this file as the release body.
- Release artifacts carry version `2.3.5` across the root, `hive-core`, `oc-arkive`, and `vscode-arkive` manifests, both lockfiles, and the generated OpenCode plugin manifest.
