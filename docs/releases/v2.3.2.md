# Agent Hive v2.3.2

Agent Hive v2.3.2 keeps frozen review topology anchored to the active session/project and preserves provider-agnostic `/dash-review` scope.

## Fixed

- Frozen review repository topology now resolves from the session/project `directory` consistently. Unrelated OpenCode global `worktree=/` metadata can no longer hide a valid project-local repository manifest. Same-session repository status, snapshot, workspace creation, claim, inspection, revalidation, and cleanup stay aligned while existing authorization and path, containment, canonicalization, and symlink checks remain enforced.
- `/dash-review` accepts descriptions, paths, tasks, features, local refs, ranges, SHAs, non-GitHub URLs, and local-checkout intent without treating them as GitHub pull requests. Command scope is deterministically JSON-framed, and Stage A has a runtime tool allowlist. An exact GitHub pull-request URL may add bounded metadata, but provider, credential, or network failure continues against the local checkout with explicit `unverified local checkout` provenance. No automatic fetch, checkout, or ref mutation was added.

## Upgrade

- Update `oc-arkive` to `2.3.2` through the normal OpenCode plugin installation flow.
- No Agent Hive configuration, data, or project-local repository-manifest migration is required.
- Restart OpenCode after updating so config-time plugin changes take effect. If OpenCode uses a cached plugin package, update that cached package before restarting.

## Release

- Tagged `v2.3.2` pushes publish `oc-arkive` to npm through Trusted Publishing, attach `vscode-arkive.vsix` to the GitHub Release, and use this file as the release body.
