# Agent Hive v4.2.0

Released: 2026-10-12

Agent Hive v4.2.0 improves two areas of the OpenCode plugin. The packaged `humanizer` skill gets a fuller rewrite workflow, and `hive_task_trace` becomes easier for agents to use correctly: trace pagination cursors are readable, and semantic recovery of an interrupted worker follows explicit output contracts and reports why it fell back. The change is backward compatible: tool names and arguments, the stored Hive state, and cursors issued by earlier versions all keep working. The VS Code companion carries only the version bump.

## Humanizer workflow

The `humanizer` skill follows the rewrite workflow from phuryn/work-humanizer (MIT, with provenance recorded in the skill's `UPSTREAM.md`). It still handles existing prose that reads as AI-written, and now also covers drafting from a writer's own material:

- **Fact list first.** Before editing, it lists every fact with its certainty. A closing fact audit checks each one against the original, including strength words such as "can help" becoming "will".
- **Fresh composition.** An AI-composed draft is rewritten fresh from its facts, and a writer's own sentences are kept as written.
- **Interview or notes.** When a draft lacks what only the writer knows, the skill asks the writer up to five questions. A delegated child returns those questions to its parent instead of inventing answers. A writer's notes or transcript can be the source for a new piece.
- **Mechanical sweep.** The optional `check.py` counts dashes, semicolons, stock vocabulary, filler transitions, and sentence-length uniformity, skipping code. Run it with `python3 <skill directory>/check.py <file>`, or pass `-` to read from stdin. It flags candidates for a second look and never rewrites.
- **Shorter option.** A "Shorter option:" note is offered only in conversation, never inside the artifact.

The neighboring writing skills move with it. `stop-slop` adds a crafted-line budget of one per piece, a sentence-length rule that varies uniform rhythm in either direction, and checks for pause-and-point lines, colon reveals, restating or engagement closers, fragment stacks, and filler transitions. `writing-for-humans` adds context-based dash substitutes and a rule against rerouting a removed dash into a semicolon. `writing-policy` routes notes, transcripts, and interview answers to `humanizer`.

## Trace cursors

A `hive_task_trace` index page now returns `coverage.next_cursor` as a readable string, `trace-cursor:v3:<prefix|source>:<after_seq>:<guard>`, instead of a base64 encoding of JSON. The guard is still the complete digest, so the integrity check is unchanged. Agents pass the whole string back unchanged as `cursor` to get the next page, and pass `events[n].ref` as `event` to `hive_task_trace_content` to read one event in detail. The tool description, the Hive Helper prompt, and the docs say so.

Cursors issued by v4.1.0 and earlier remain valid, including ones already held in a stored conversation. A malformed cursor returns `invalid_cursor` with a hint to pass `coverage.next_cursor` unchanged or omit `cursor` to restart. Event refs and recovery content IDs keep their existing format.

## Semantic recovery

Recovery (`hive_task_trace` with `recovery: true`) summarizes an interrupted worker's surviving session through a hidden summarizer. It remains untrusted context and never authorizes accepting, merging, retrying, or resuming anything. In v4.2.0:

- **Explicit output contracts.** Each stage's request carries a strict JSON Schema built from the same schema that validates the reply, plus the rules a schema cannot express. Unknown or missing keys, blank strings, and wrong step ranges are rejected. A malformed map card falls back on its own step while valid sibling cards are kept. The reply must be a bare JSON object, or that object inside a single code fence, and nothing is extracted or repaired from surrounding prose.
- **Model and variant handling.** The configured `model` and `variant` are included on each summarizer request that is sent, and `temperature` is applied to the hidden summarizer agent. `recovery.model.observed` reports the provider, model, and variant the host says it ran. When provider metadata shows the model does not offer the configured variant, no summarizer session is created and no prompt runs; recovery falls back deterministically with a `variant_unavailable` diagnostic and does not report the variant as applied. If that metadata cannot be read, the variant is still sent.
- **Native errors and fallbacks.** A provider error reported in the response, an unusable or oversized reply, or a request above the model's input budget produces a deterministic partial fallback, with no provider retry or model fallback.
- **Bounded diagnostics.** A failed stage may carry up to four `diagnostics`: finite codes, a schema path and step number, the provider error name and HTTP status, the finish reason, and the reply size. They never include provider messages, response bodies, source text, or model text.
- **Grounded completion claims.** A completed claim must cite at least one step from `completion_steps`, the assistant steps with observed evidence or plaintext reasoning that the reduce request lists. It may also cite a user-request step, but a user request alone cannot support it. An unfinished claim can cite a user request alone. When `completion_steps` is empty, the safest next action is `inspect`.

## Upgrade from v4.1.0

1. Set the OpenCode plugin entry to `oc-arkive@4.2.0` and update any cached plugin package. Download `vscode-arkive.vsix` from the v4.2.0 GitHub Release and install it with `code --install-extension ./vscode-arkive.vsix`.
2. Restart the process that hosts the plugin. For a long-lived server managed by `opencode.service`, restart that service, confirm it started after the update, and start fresh sessions so agents load the updated skills and trace guidance.
3. Nothing needs migrating. Keep passing `coverage.next_cursor` and `events[n].ref` exactly as returned, without decoding or rebuilding them. If scripts read `recovery` output, expect the optional `diagnostics` array on failure entries.
