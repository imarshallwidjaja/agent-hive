# Agent Hive v5.2.0

Released: 2026-10-31

Agent Hive v5.2.0 adds a dedicated Investigator role, crash-safe native locks and guarded recovery for interrupted worktree operations. Integration now requires an explicit choice between preserving source history and rewriting private history. This minor version intentionally carries compatibility changes; read the upgrade instructions before restarting any host.

OpenCode support remains v1 >= 1.18.30 and v2 qualified on 2.0.26 only. The VS Code companion now requires VS Code 1.67.0 or later.

## Install and upgrade

1. Stop all older OpenCode processes, workers and Git children, and all VS Code instances that can write the same project **or shared global Hive configuration**. Hosts using the old and new locking protocols cannot safely share writers. Stopping one project's host is insufficient when another host can write the same `~/.config/opencode/agent_hive.json`.
2. Inspect legacy lock files: `<file>.lock` beside state files or the global configuration, feature `.plan-patch.lock` directories, and `.hive/.operation-locks/` entries. Once their older writers are confirmed stopped, remove only confirmed legacy state locks and plan-patch lock directories. Retain legacy operation locks and interrupted-operation markers for guarded recovery after the upgrade. Preserve permanent `.hive/.locks/` anchors and global-config `.hive-lock` anchors.
3. On OpenCode v1, set the plugin entry to `oc-arkive@5.2.0`, or refresh the cached `@latest` package. On v2, install the version into a dedicated directory and point `plugins` at its installed `dist` directory:

   ```bash
   mkdir -p /absolute/install
   cd /absolute/install
   npm install oc-arkive@5.2.0
   ```

   The [plugin README](https://github.com/imarshallwidjaja/agent-hive/blob/v5.2.0/packages/opencode-hive/README.md#opencode-v2) covers v2 options, server configuration and host setup.
4. Install `vscode-arkive.vsix` from this GitHub Release with `code --install-extension ./vscode-arkive.vsix`. Its minimum changes from VS Code 1.64.0 to 1.67.0 because the native Koffi dependency requires Node 16.
5. Start the upgraded long-lived host process, such as the `opencode` TUI, `opencode serve`, or its service, and open a primary session. Restarting an attached client does not reload the server's plugin. Send a new message before using Hive tools and launch fresh child sessions.
6. Before ordinary worktree mutations, have the upgraded primary inspect retained operation locks and interrupted-operation markers with `hive_worktree_recover`. This tool is unavailable in v5.1.0. Confirm every operation process has stopped and resolve any open Git operation, then obtain fresh `markerDigest` and `observedStateDigest` values from a new listing. Acknowledge the exact entry with those digests and `mutatorsStopped: true`, following the guarded recovery procedure below. Recovery clears only the acknowledged records; inspect again before deciding what work remains.
7. Update custom merge callers and copied instructions to supply `historyIntent` as described below. Existing plans, tasks, context and Worklogs need no wholesale format conversion. Earlier model and configuration migration requirements still apply when upgrading from before v5.1.0; see the [Operator Guide](https://github.com/imarshallwidjaja/agent-hive/blob/v5.2.0/docs/OPERATOR-GUIDE.md#upgrade).

## Compatibility changes

### Explicit history intent

Both `hive_worktree_merge` and `hive_adhoc_worktree_merge`, and their core service APIs, require `historyIntent`. There is no default:

- `preserve-source` keeps source ancestry and historical commit messages. It permits only `strategy: "merge"`, which is also its default.
- `rewrite-private` declares that all source-only history in every selected repository is private and may be rewritten. It permits `squash` (the default) or `rebase`.

New merge and squash commits require a nonblank one-line subject, a blank line and a descriptive body. Rebase rejects a nonblank `message`; private replay validates source messages. Published history must use `preserve-source`.

A source already contained in the destination returns `ALREADY_INTEGRATED` after identity, cleanliness and active-operation guards, before topology/local-data eligibility checks. That no-op needs no commit message. `NO_TRACKED_CHANGES` alone does not establish ancestry. Before same-call cleanup, Hive rechecks source and destination identity and requires source containment for preservation and already-integrated outcomes, or verified completion with the private-history attestation for private rewrites and content no-ops. A failed proof retains the source placement. Read `reasonCode`, `action`, `cleanup` and any `finalization` block even when `success` is true.

### Native lock dependency

`hive-core` and `oc-arkive` now depend on the exact `koffi@2.16.3` native module. The VSIX includes its loader, metadata, license and prebuilt binaries for the platforms and architectures supplied by Koffi. Hive uses operating-system locks (`flock` on supported POSIX systems and `LockFileEx` on Windows) and fails lock-dependent operations if the native backend cannot load; it has no unsafe fallback.

The operating system releases lock ownership when the process exits. Stable lock anchors remain on disk, and their PID/timestamp text is diagnostic, not ownership proof. Never delete current lock anchors to recover an interrupted operation.

## What is new

### Investigator and experiment assignments

`forager-investigator` is a built-in subagent and custom-agent base for standalone diagnosis, experiments, source assessments and verify-only checks. It returns evidence and a conclusion, commits nothing and delivers no product patch. Its Hive grants cover reads and worktree inspection; it receives the route snapshot without a Forager task brief or task-report duty, cannot delegate or ask questions, and loads `verification` by default. Implementation-coupled diagnosis remains with the implementation Forager.

Hive, Swarm, Hive Builder, Architect and the review primaries share an experiment method that names authority, candidate, variants, placement, evidence and cleanup. Source-changing probes run in a disposable placement owned by the primary. A runtime target can instead name a URL, session or environment; a source assessment needs no execution placement. An unchanged original checkout is a guarded fallback only when the assignment authorizes it and a disposable placement cannot carry the candidate faithfully.

Architect can commission Investigators, including as a delegated planner, but cannot dispatch implementation Foragers. A primary Architect can create and clean up experiment placements and never merges them. Review primaries now use Investigators instead of Foragers for runtime exercises; specialist reviewers remain non-executing. A review request alone does not authorize a runtime exercise.

### Interrupted operations and durability

Worktree operations lock their workspace and selected repositories' Git common directories, then recheck their selection. Before their first mutation they publish pending markers for the protected resources. A Git child can outlive the host, so a released native lock alone is not permission to retry. Unknown outcomes retain markers and later mutations report `OPERATION_RECOVERY_REQUIRED`; inspections remain available and expose `pendingOperations`.

`hive_worktree_recover` lists interrupted operations and legacy operation locks, including entries whose workspace is gone. A primary confirms that every process of the operation has stopped, resolves any open Git operation, then acknowledges the exact `operationId`, `markerDigest` and `observedStateDigest` with `mutatorsStopped: true`. Recovery validates trusted paths and Git linkage, refuses changed records or state, and removes only the acknowledged records. It never replays, retries or rolls back the operation. Inspect again before deciding what work remains.

Marker publication and removal flush files and directories where supported. Finalization errors retain the operation's result and separately describe marker-removal or lock-release failures. A `cleared_unflushed` result means the files were removed but the directory flush failed, so the removal may not survive a crash. These are bounded durability guarantees, not a claim that every state write is crash-durable. Follow the [recovery contract](https://github.com/imarshallwidjaja/agent-hive/blob/v5.2.0/packages/opencode-hive/docs/HIVE-TOOLS.md#interrupted-operations-and-recovery).

### Repository topology fix

Legacy `repositoryRoot`/`repositories` resolution and migration now validate the topology separately from unrelated agent settings. An invalid model or unknown configuration key no longer hides valid topology. Malformed JSON, a non-object root or an invalid topology pair still fails. Cleanup removes only a matching topology pair and preserves other stored settings, including values that a full configuration read would reject or ignore.

### Writing and verification guidance

- `writing-for-humans` adds technical and product clarity checks and examples for actors, reader-relative terminology, conditions, comparisons, identity and evidence. Requested product-alignment notes use short task-based sections, list-led ideas and brief commentary, while retaining continuous prose for reasoning.
- `project-verification` keeps run-specific decisions and evidence in session/work logs or untracked artifacts. Versioned guidance records shared current procedures, contracts and requirements. Explicitly required scientific provenance and reusable fixtures may stay versioned, and required evidence must survive cleanup.
- Durable-lock fixtures allow bounded time for slower startup. The VS Code context viewer probes active native and legacy locks without writes and ignores internal lock events to prevent refresh loops.

## Known limits

- Native locking has been exercised on Linux x64 under Node and Bun. The other platforms' prebuilt binaries are packaged, but that is not all-platform runtime validation. Windows has no portable directory flush through Node, so directory-flush durability is not claimed there.
- OpenCode v2 qualification remains limited to 2.0.26. This release makes no new cross-model or cross-provider behavioral qualification claim for the instruction changes.
- Operator confirmation that mutators stopped remains necessary: empty Git lock state does not prove that every child process has exited. Locks coordinate participating Hive writers, not arbitrary external Git or filesystem writers.

## Release artifacts

The root, `hive-core`, `oc-arkive` and `vscode-arkive` manifests and generated OpenCode plugin manifest carry version `5.2.0`. Both root lockfiles and the tracked VS Code bundle are regenerated; OpenCode and VS Code pin local `hive-core` to exact `5.2.0`.

The release workflow publishes `oc-arkive` to npm and attaches `vscode-arkive.vsix` to the GitHub Release, using this file as the release body. The [release guide](https://github.com/imarshallwidjaja/agent-hive/blob/v5.2.0/docs/RELEASING.md) covers preflight, rehearsal and tag-backed recovery.
