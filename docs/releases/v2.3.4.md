# Agent Hive v2.3.4

Agent Hive v2.3.4 extends the existing frozen Git `/dash-review` workflow with inline and local-artifact evidence, corrects OpenCode global-context detection, and updates AGENTS.md maintenance guidance.

## Added

- `/dash-review` accepts exactly one evidence kind per invocation: Git, inline `process`, `concept`, or `general` intent, or packet-fixed project-relative files supplied with repeatable `--artifact` flags. Mixed kinds, arbitrary URLs, private or traversing paths, and symlinks fail before acquisition. Inline and local-artifact evidence uses advisory, approach-advisor-derived lanes rather than Git implementation-review semantics. Local-artifact bundles accept at most 32 files, 16 MiB per file, and 32 MiB total; the Operator Guide has the command loop.
- Stage A resolves that kind once through the one-shot `hive_review_evidence_resolve` tool and returns runtime-owned fingerprints before a frozen workspace is created. Deep review runs only after freeze. Claim, inspect, and cleanup are restart-safe from persisted ownership. After a handoff or owner-recovery lease expires, claim and authorization recovery fail closed; cleanup of that expired run can still remove the workspace. `/vuln-review` remains Git-only.

## Changed

- Review workspace creation accepts the invocation-bound resolution fingerprint rather than caller-supplied refs, repositories, paths, inline bytes, artifact paths, or scope claims. `/vuln-review` continues to accept Git evidence only and preserves its existing two-stage fail-closed state machine.
- `agents-md-mastery` now places durable rules progressively in the nearest applicable AGENTS.md, records only commands and conventions that exist, and prunes sentences that would not change an agent decision.

## Fixed

- `/dash-review` now authorizes Stage A, primary, and deep-lane actions against exact runtime agent names and task targets, consumes one-shot evidence authority, and recovers persisted workspace ownership after restart. Frozen-workspace path checks prevent review lanes from falling back to the live checkout. Validated Git provenance remains attached to Git reviews.
- Only an exact standalone GitHub pull-request URL is translated into Git evidence. The public `githubPullRequest` packet field is preserved. Prose-embedded, parenthesized, or multiple URLs fail closed before acquisition; pass the bare URL.
- OpenCode global non-Git contexts that report `project.id=global` and `worktree=/` now use the project directory for Hive context detection and writes. Real worktrees continue to control worker ownership and mismatch protection.

## Upgrade

- Update `oc-arkive` to `2.3.4` through the normal OpenCode plugin installation flow.
- No Agent Hive configuration, data, or project-local repository-manifest migration is required.
- Restart OpenCode after updating so config-time plugin changes take effect. If OpenCode uses a cached plugin package, update that cached package before restarting.

## Release

- Tagged `v2.3.4` pushes publish `oc-arkive` to npm through Trusted Publishing, attach `vscode-arkive.vsix` to the GitHub Release, and use this file as the release body.
