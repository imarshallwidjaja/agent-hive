# Agent Hive v4.1.0

Released: 2026-10-10

Agent Hive v4.1.0 changes how implementation review works. Reviewers now judge a change in the context of the system it touches and report only findings that survive their own attempt to disprove them. Primaries give reviewers focused context, size review by risk through one shared policy, and run a bounded review-and-fix loop. Tool contracts and stored Hive state are unchanged.

## Reviewer method

Code and simplicity reviewers, including custom reviewers derived from them, follow a shared investigation method:

1. **Orient** on what the change must achieve and the contracts, interfaces, persisted shapes, or reader-facing behavior it touches.
2. **Notice** leads before verifying any. Reviewers generate their own leads first, then add the primary's, and look hardest where human reviewers skim: deletions, consumers of changed contracts, sibling implementations that should have moved too, silent behavior changes, and applicable project rules.
3. **Verify** the most consequential leads through call sites, tests, history, and contracts.
4. **Disprove** each candidate by looking for the guard, the caller that never passes that input, the test that already pins the behavior, or the contract that permits it.
5. **Report** only survivors, anchored to `file:line` with the quoted line and a `Survived:` note. Style preferences and minor pre-existing issues stay out. Drift the change creates in an untouched sibling is the change's finding, and a serious pre-existing defect found on a traced path is reported marked `(pre-existing)`.

Both reviewers end with a `### Coverage` section listing cleared leads and areas not inspected. The simplicity reviewer's `### Not Worth Changing` section is replaced by `### Coverage`. Reviewer inspection stays read-only; reviewers name any install, build, test, or reproduction for the primary to run unless the assignment authorizes it.

## Review packet, routing, and follow-up

- **Review packet.** For implementation review, primaries add a focused packet to the existing handoff pointers: purpose, comparison base, touched boundaries with consumers, siblings, and owning tests, relevant lenses, unverified leads, worker evidence, and for a re-review the prior findings, prior coverage, and fix range.
- **Review Routing.** Hive, Swarm, and Hive Builder share one policy. Ad-hoc lanes are reviewed before merge and feature batches after each merge. Source changes get paired correctness and simplicity review by default. Renames, formatting, one-line fixes, and bounded docs or tests get one review; when unsure, the primary pairs. High-risk surfaces add the companion passes configured reviewer descriptions call for, and verification-only gates skip extra review. Hive Builder's lifecycle has an explicit Review step before completion.
- **Review Follow-Up.** The primary spot-checks quoted anchors and adjudicates by evidence. A contested material finding gets the discriminating check it names or a fresh reviewer that did not raise it. Accepted minor fixes are folded into one remediation round and confirmed against the fix diff; minor-only results do not reopen review. Material work is re-reviewed in a fresh session, and the loop stops when no accepted material finding remains open.

`/dash-review` keeps its independent challenge of every material candidate and now passes the review packet to implementation reviewers.

## Upgrade from v4.0.0

1. Set the OpenCode plugin entry to `oc-arkive@4.1.0` and update any cached plugin package. Download `vscode-arkive.vsix` from the v4.1.0 GitHub Release and install it with `code --install-extension ./vscode-arkive.vsix`.
2. Restart the process that hosts the plugin. For a long-lived server managed by `opencode.service`, restart that service, confirm it started after the update, and launch fresh child sessions so reviewers load the new prompts.
3. If scripts or copied instructions parse reviewer output, read `### Coverage` instead of `### Not Worth Changing`. Copied primary instructions that restate review tiers should point to Review Routing instead.

Paired review is now the default for source changes in feature execution, which previously paired only high-risk surfaces. Expect more review calls per batch.
