# Expected-file example

This reference adds method, not authority. It shows one case under the Case Rules in SKILL.md: a CLI driven through its installed entry point, every promised observable asserted, one reasoned normalizer, and a full diff against an expected file. Port the shape to the project's own runner; the local contract decides where files live.

## The requirement

`invoice-total` reads CSV lines `item,quantity,unit_cents` on stdin. It prints `total: <cents>`, the sum of quantity times unit price, then one `generated:` line with an ISO-8601 UTC time. It writes nothing to stderr and exits 0.

## Input and expected file

`tests/cli/cases/two-lines/input.csv`:

```csv
widget,2,250
gadget,1,1999
```

The requirement gives 2 x 250 + 1 x 1999 = 2499 cents. The contract leaves the generation time open, so the expected file holds a placeholder where the normalizer puts one.

`tests/cli/cases/two-lines/expected.stdout`:

```text
total: 2499
generated: <timestamp>
```

## The case

`tests/cli/invoice-total-two-lines.sh`:

```bash
#!/usr/bin/env bash
set -euo pipefail

# Requirement (docs/cli.md, "invoice-total"): print "total: <cents>", the sum of
# quantity * unit price over the input lines, then one "generated:" line with an
# ISO-8601 UTC time; write nothing to stderr; exit 0.
case_dir=tests/cli/cases/two-lines
in="$case_dir/input.csv"
expected_out="$case_dir/expected.stdout"
expected_status=0

tmp=$(mktemp -d)
trap 'rm -rf "$tmp"' EXIT

# The installed entry point, run as a consumer runs it. Capturing the status this
# way keeps set -e from stopping the script before a rejection case can assert it.
status=0; invoice-total < "$in" > "$tmp/out" 2> "$tmp/err" || status=$?

if [ "$status" -ne "$expected_status" ]; then
  echo "FAIL: exit status $status, expected $expected_status" >&2
  cat "$tmp/err" >&2
  exit 1
fi
if [ -s "$tmp/err" ]; then
  echo "FAIL: unexpected stderr:" >&2
  cat "$tmp/err" >&2
  exit 1
fi

# Permitted variation: the generation time, which the contract leaves open.
# Exactly one well-formed line must be present; otherwise the case fails instead
# of diffing raw output.
stamp='^generated: [0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$'
if [ "$(grep -Ec "$stamp" "$tmp/out")" != 1 ]; then
  echo "FAIL: expected exactly one well-formed generated: line" >&2
  cat "$tmp/out" >&2
  exit 1
fi
sed -E "s/$stamp/generated: <timestamp>/" "$tmp/out" | diff -u "$expected_out" -
```

What each part guards:

- **Exit status first.** A run that prints exactly the expected text but exits 3 fails on the status line. Matching text with the wrong status is a failure, so the status assertion is never optional.
- **stderr is promised too.** A success that also writes a warning fails, even when stdout matches.
- **The normalizer is narrow and checked.** It replaces only a well-formed timestamp, and a missing or malformed `generated:` line fails the case before the diff. A malformed line that slipped past would stay raw and fail the diff. It never touches the total, which the requirement specifies.
- **`diff -u` is the assertion.** A wrong total shows as a one-line hunk, for example `-total: 2500` against `+total: 2499` when the expected file is wrong.
- **One temporary directory and a trap** keep captured output out of the checkout and remove it on every exit, including a failure.

A rejection case keeps the same skeleton. Give it otherwise-valid input that violates the intended guard, for example `widget,-2,250` for "quantity must be positive", set `expected_status` to the code the contract specifies, and diff stderr against an `expected.stderr` file instead of requiring it empty.

## The record

The record goes in the commit or PR description and the worker's report or handoff, never in the expected file.

For a new expected file:

```text
tests/cli/cases/two-lines/expected.stdout (new): checked against docs/cli.md
"invoice-total". total = 2 x 250 + 1 x 1999 = 2499 cents. The generated: line
is normalized because the contract lets the time vary.
```

For a later grouped change, regenerated by a script:

```text
Expected files: 14 changed, regenerated with tests/cli/update-expected.sh.
- "total:" lines gain " EUR" after the amount (14 files): docs/cli.md now
  requires the currency code after the total (issue #212).
- "generated:" line moves above "total:" (14 files): the same docs/cli.md change
  puts the header first.
No other hunk kinds.
```

Each hunk kind maps to the requirement change behind it. A hunk outside those two kinds is not part of the update: investigate whether it is a regression, a permitted variation that needs a normalizer, or a correction against an unchanged requirement.
