# Selective pstack material

`SKILL.md` and `references/formal-verification.md` adapt four skills by Lauren Tan from pstack 0.15.32, `cursor/plugins` revision `c5149ef275fa7be41e3ffe5e79c8fc16efcaeedc`: `create-verification-skill`, `maintain-verification-skill`, `create-formal-verification-skill`, and `maintain-formal-verification-skill`. Source: https://github.com/cursor/plugins/tree/c5149ef275fa7be41e3ffe5e79c8fc16efcaeedc/pstack/skills . `LICENSE.pstack` is the pstack `LICENSE` at that revision and covers the adapted passages; it is identical to the copy in `verification`.

## What is kept

- From the verification pair: interview the repository before the user; drive the real user path and verify side effects; readiness means usable; isolate instances and refuse to double-drive a shared one; cleanup removes what a run started and keeps the evidence; prove the generated material by following it once as the next agent would, and treat an unrun one as a draft; never weaken a journey to make it pass; separate doc drift, harness gaps, and product failures, and keep product fixes out of verification changes.
- From the formal pair: choose the target by harm and by how rarely tests reach it, not by ease; let the question choose the tool and prefer one the project can run; keep the model true to the code, including atomicity, new writers, and moved code; show each property failing on a negative control; findings stay findings, with counterexamples retold in the code's terms; state bounds and assumptions; record covered code and the last confirmed commit; run an existing check as it stands before updating it, update from the code rather than the result, and replay counterexamples against the code to tell drift from a bug.

## Deliberate adaptations

- **One conditional skill instead of four user-invoked generators.** Upstream ships `disable-model-invocation` slash commands that generate a project-local `.cursor/skills/verify-<app>/` skill. Here one model-invoked skill applies only when durable verification capability is the requested or assigned work, and ordinary tests, fixtures, and probes stay ordinary work. No slash command, native skill adapter, or generated skill is created by default; a requested native-skill variant must be loaded through the native skill tool and match the candidate under test.
- **Discovery through `AGENTS.md`, without a fixed layout.** Upstream fixes the skill path, a `features/` directory, and four headings per feature file. Here the repository's applicable `AGENTS.md` holds concise guidance or a scoped pointer to a canonical guide, whose location, filename, and headings follow the project. `verification` owns that routing for every agent. The guide's required content is listed, not its schema, and it points to existing executable definitions instead of copying command, test, or CI inventories.
- **Authority and scope.** Upstream fixes the checkout, creates scaffolding, opens one pull request per maintenance pass, and edits the verification directory freely. Here the role and assignment set authority, tooling and dependencies are scoped with the project's operators, the `AGENTS.md` entry needs item-level approval under `agents-md-mastery`, verify-only work is a report-only diagnosis, and no periodic job, pull request, or installation is required.
- **Expected-behavior basis.** Added: each claim records what says it is correct (specification, public contract, operator decision, or independently derived values), distinct from observed current behavior.
- **Check validity apart from product results.** Added: a working check that finds a product failure is reported as a valid check with a failing product result, separately from covered scope and discoverability. Interpretation and proof-strength limits live in `verification`.
- **Maintenance evidence.** Added: a failure on an equivalent base shows preexistence, not harness drift; unchanged assertion text does not show unchanged coverage when inputs narrowed; changing guarantees, skips, retries, tolerances, assumptions, bounds, or gate obligations needs covering authority and visible impact.
- **Run records.** Run-specific decisions and evidence stay in logs or untracked artifacts; versioned guidance states shared current rules. Explicitly required scientific provenance and reusable fixtures may remain versioned.
- **Formal method is disclosed and optional.** The formal method is a reference read only when the requested capability uses formal tools. TLA+ is not named as a default, no tool is installed by default, and the upstream pointer to the pstack `statechart` skill is not imported because that skill is not available here. Upstream asks for a broken variant of the real code for every property. Here the negative control breaks the surface the check actually reads: code for a verifier that runs on the code, the model for a detached model, whose control shows only model sensitivity for design analysis. A claim that the check detects code defects needs an observed connection from mutated source to the check. No proof obligation applies to ordinary changes.
- **Not imported.** The parallel per-feature source-reader wave, the single live coordinator, the clean/changed/blocked and in-sync/updated/bug outcome vocabularies, the seeded feature map and its example files, and the cadence offer.
