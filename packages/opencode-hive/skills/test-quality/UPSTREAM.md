# Selective pstack material

The common lens migrated from `test-driven-development/references/test-quality.md`. It adapts Lauren Tan's `principle-test-behavior-not-implementation` from pstack 0.15.25, `cursor/plugins` revision `09d06eb4b97a1020ab31e84030e38baf1099c7dc`, and `tdd` from pstack 0.15.5, `cursor/plugins` revision `fae2c6ed95821bd85f614a73e4842e13229fa5e5`. Sources: https://github.com/cursor/plugins/tree/09d06eb4b97a1020ab31e84030e38baf1099c7dc/pstack/skills and https://github.com/cursor/plugins/tree/fae2c6ed95821bd85f614a73e4842e13229fa5e5/pstack/skills . `LICENSE.pstack` covers those passages; the license text is identical at both revisions.

Revision history: the 0.15.5 import asked whether a test would still pass if every imported function returned undefined. The 0.15.25 principle replaced that heuristic with two counterfactuals: a plausible break of the observable contract should fail the test, and a behavior-preserving private refactor should pass it. Observable return values, errors, readable state, external effects, boundary mock payloads, and credible absence checks remain valid.

Deliberate adaptations: require an independent oracle and exercised product path, distinguish pure setup assertions from product-mutated state readbacks, preserve metamorphic oracles and distinct layer-specific faults, and recognize delivered prompt/configuration/package/type contracts without claiming model compliance. The suite-audit branch adds evidence-backed recommendations and honest coverage limits. Audits are report-only; explicit remediation follows existing role authority and implementation checks. No mutation framework, benchmark campaign, TDD selection, automatic deletion, or universal implementer load is added.

# caldoai prune-tests

The prune mode and `references/prune.md` adapt caldoai's `prune-tests` skill at `caldoai/skills` revision `bd73b2ea5eb854ab8f0553fb41f77c8786f28f82`. Source: https://github.com/caldoai/skills/blob/bd73b2ea5eb854ab8f0553fb41f77c8786f28f82/skills/prune-tests/SKILL.md . `LICENSE.caldoai` is the MIT notice from that revision.

Adapted: the imperative action shape, the classification by what a weak test depends on (the implementation, nothing, the past, another test), deleting or rewriting against behavior, removing code that existed only for deleted tests, a done list, and a worked diff.

Deliberate departures: an audit or a "which tests should we remove?" question never deletes tests; prune acts only on an explicit request within a settled scope. The past becomes an obsolete requirement: the contract decides whether an absence check stays, not whether the code once existed or a generator could restore it. Duplicates at different layers that catch distinct faults are kept, and a fold names a same-layer owner. "Nothing" excludes tests that exercise a repository-owned boundary. Removal of test-only production code is narrowed to support code whose consumers and public contracts were checked, and keeps seams, published exports, and indirectly called protocol methods. A probe step introduces one fault before a doubtful deletion.
